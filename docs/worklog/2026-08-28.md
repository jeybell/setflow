## 세부작업 설명

### PR #213 — 곡 삭제 버튼 이동 + 악보 관리 UI 간소화
- 스크린샷 지시대로 곡 제목 옆에 삭제(휴지통) 아이콘을 추가하고, 기존 '곡 관리' 섹션(제목+삭제 버튼)을 제거.
- 이어서 "악보 관리 화면이 버튼이 너무 많다"는 후속 피드백에, 구체적으로 어느 버튼인지 되물어(스크린샷 없이 임의 판단하지 않기 위해) 범위를 확정한 뒤: 악보 버전 카드의 '수정'/'삭제' 텍스트 버튼을 아이콘 전용으로 축소, 파일 목록의 '배경 흰색으로 저장' 바로가기 아이콘 제거(상단 메인 뷰어에서 이미 동일 기능 접근 가능한 중복 경로였음), 파일 업로드를 '파일 선택'+'업로드' 2단계에서 자동 업로드 1단계로 축소.
- 가사 섹션은 "잘 안 써서 지우거나 기본 비노출로"라는 요청에, 확인해보니 이미 기본 접힘(collapsed) 상태였음을 알리고 세 가지 선택지(현상 유지/UI만 숨김/완전 삭제)를 물어 "UI만 숨김, 데이터·API는 유지"로 결정. `<Card v-if="false">`로 감싸 렌더링만 막고 스크립트 바인딩은 그대로 둬 `noUnusedLocals` 빌드 옵션에도 안전하게 처리.

### PR #213 머지 사고 발견 → PR #214에서 재적용
- 다음 작업(악보 관리 버튼 완전 제거) 요청을 받고 최신 main을 받아 코드를 열어보니, **PR #213의 두 번째 커밋(가사 숨김·아이콘 버튼 정리 등) 내용이 main에 없었음.** `git log`로 확인한 결과 PR #213의 머지 커밋(`6bcf0f5`)의 두 번째 부모가 최종 push한 커밋이 아니라 그 이전 커밋이었음 — 즉 머지가 실제 최신 head보다 오래된 상태를 기준으로 이루어짐. 정확한 발생 메커니즘(브라우저 페이지 캐시로 인한 stale head 병합 추정)은 끝내 확인하지 못함.
- 대응: 사라진 커밋을 `git cherry-pick`으로 새 브랜치에 재적용 → 정상적으로 clean 적용됨. 이 위에 원래 요청(악보 관리 버튼 제거, 악보 섹션 기본 노출)을 이어서 구현. PR 본문에 사고 경위를 명시하고, 이번엔 머지 시 최신 head 확인을 요청.

### Vercel 빌드 실패 — `vue-tsc --noEmit` vs `vue-tsc -b`(실제 빌드 커맨드) 불일치
- PR #214 푸시 후 Vercel 프리뷰 빌드가 실패(Error). 로컬에서 `npm run build`(package.json 스크립트, 실제로는 `vue-tsc -b && vite build`)를 그대로 돌려 재현: 숨긴 '가사' 섹션 안 `song.lyrics` 접근에서 `song`이 null일 수 있다는 타입 에러 2건 발생.
- 그런데 작업 내내 검증에 써온 `npx vue-tsc --noEmit`은 같은 코드에서 에러 없이 통과했음 — **두 명령의 타입 체크 결과가 달랐다.** `-b`(프로젝트 참조/빌드 모드)가 `--noEmit` 단독 실행보다 엄격하거나 다른 파일 세트/설정으로 체크하는 것으로 보임(정확한 내부 동작은 미확인).
- 수정: `song?.lyrics` 옵셔널 체이닝을 두 곳에 추가. 이번엔 `npm run build`로 직접 재현·검증 후 푸시해 Vercel 재빌드 성공 확인.

### PR #215 — 악보 버전 아코디언 ↔ 슬라이드 양방향 동기화
- 기존에는 상단 슬라이드(하단 키 썸네일)를 넘기면 오른쪽 '악보' 아코디언이 그 버전으로 펼쳐지는 단방향 동기화만 있었음(이전 세션 작업, PR #212).
- "반대 방향도 동일하게"라는 요청으로, 아코디언에서 버전을 펼칠 때(접을 때는 제외) 해당 버전의 첫 슬라이드 인덱스를 찾아 상단 슬라이드도 이동시키는 로직을 `toggleSheet` 함수에 추가. 기존 반대 방향 watch와 값이 같아지면 재트리거되지 않는 Vue ref 특성 덕분에 무한 루프 없이 안전하게 공존.

### PR #216 — 악보 목록 필터 영역 sticky 처리
- "스크롤해도 검색/필터 영역이 고정됐으면 좋겠다"는 요청(빨간 박스 스크린샷)에, 전역 헤더(`DefaultLayout`)가 이미 `sticky top-0`인 것을 확인하고, 그 바로 아래(`top-12 sm:top-14`, 헤더 높이와 동일)에 페이지 제목·검색·태그·정렬 영역을 별도 `sticky` 컨테이너로 감쌈. 테스트 곡 30개를 등록해 실제 스크롤 시 헤더/필터가 고정되고 카드만 스크롤되는 것을 스크린샷으로 확인.
